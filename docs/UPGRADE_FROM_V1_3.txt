七音音乐工作室：v1.3 → v1.4.0-public.1 应用资源更新
请先读完本说明，再复制任何文件。

一、这是什么
这是给已有 Windows x64 客户端使用的小型应用资源更新包，不是独立客户端。
包内 resources\app 是公开基础版的完整应用资源，不含 Electron，不需要重新下载已有 EXE / Electron。
不含 Python、模型、TensorFlow、ONNX Runtime、额外 FFmpeg、Audiveris、Java、OCR 数据或 Visual C++ 安装器。
已有识别组件留在原位置；保留文件不代表已验证它们与新版完全兼容，也不表示它们可以公开再分发。
普通作曲 / 音效 / 高级作曲使用随包的本地资源。可选识别组件的用途、官方来源与安装方法见更新后的：
resources\app\docs\COMPONENT_SETUP.md

二、适用前提（必须满足）
- Windows 10/11 x64；已有完整、可正常启动的“七音音乐工作室 v1.3 Windows x64 客户端”。
- 旧版 resources\app\package.json 的 version 为 1.3.0，main 为 desktop/main.cjs；不是只有网页资源的浏览器包，也不是 app.asar 封装。
- 原始客户端 ZIP 文件名：七音音乐工作室-v1.3-Windows客户端-x64.zip
- 原始 ZIP 字节数：163412729
- 原始 ZIP SHA256：b9b4c13561875c6173ad1186bb5b97bc791b0c7976de620280f421b3139a926f
- 原始客户端使用 Electron 44.5.1 Windows x64。该更新只更换应用资源，不升级 Electron、系统组件或安全软件。
- 安装目录需有写入权限。不要在 ZIP 内操作，不要只移动 EXE，不要绕过系统安全警告。
如果你的版本、目录结构或来源不同，先停止，不要强行覆盖。自行修改过的代码、范例或其它文件应另外留存，不会自动迁入新版应用目录。

三、先保存正在做的作品
1. 在仍能打开的旧版中，分别保存各工作区。仅保存一个工作区并不能保存其他工作区。
   - 数字作曲：保存工程 JSON；重要作品另外导出 WAV / MIDI。
   - 高级作曲：通过“文件 → 导出歌曲”保存 JSON；有需要再导出音频 / MIDI。
   - 音频识别：保存 .transcription.json；它不包含原音频，请另存原始输入、每条需要保留的原始分轨 WAV 和重要导出。
   - 乐谱：保存 .七音乐谱.json，并保留重要的原始谱文件与导出。
2. 完成 Windows 保存对话框，检查文件确实存在且大小非零。文件会保存到你选择的位置；客户端默认建议 Windows“下载”文件夹，但你可能选过其它目录。
3. 识别服务的临时任务不是永久保存。先完成导出，再取消任务或关闭客户端。
4. 完全退出七音和它启动的识别任务。不要在程序运行中复制、改名、更新或恢复配置。

为什么不能只依赖“自动保存”：主界面与高级编辑器会使用浏览器本地存储，客户端服务每次启动使用动态的本机端口。浏览器存储按来源隔离，升级或重启后不保证重新找到上次草稿。导出到独立文件的 JSON 才是本说明建议的迁移依据。保留用户配置备份也不能替代手工导出，更不能保证恢复从未保存的修改。

四、备份（不删除任何旧文件）
1. 最稳妥的方法：退出程序后，把整个现有客户端目录复制到另一个备份目录。不要移动原目录；保持以后启动的原路径不变，有助于保留依赖的绝对路径。
2. 确认备份包括：resources\app、客户端根目录的 .runtime（若存在）、你放在客户端内的工程 / 音频 / 图片 / 乐谱以及其它自定义文件。
   .runtime 保存可选识别依赖、模型、缓存、准备状态；.runtime\score-omr\score-omr.json 保存已选择的 OMR 程序路径。本更新不会复制或覆盖 .runtime。
3. 把保存到“下载”“文档”或其它位置的作品、原音频和导出也复制到备份处。这些文件不会自动集中存到客户端目录。
4. 还可在资源管理器地址栏输入 %APPDATA%，备份其中已有的“七音音乐工作室”和“qiyin-music-studio”文件夹（若存在）。客户端未自定义 Electron 用户数据路径；实际创建了哪个目录未在 Windows 实机确认。这里可能包含 Chromium 偏好及本地草稿，请保留已有目录，不要清理或用空目录覆盖。
5. 备份完成后保留一份原始 v1.3 ZIP。不要删除唯一的备份。

五、推荐更新步骤：旧 app 留作备份，新 app 整体放入
本包没有安装脚本，不会自动写入你的电脑。以下操作在 Windows 资源管理器中完成：
1. 把本更新 ZIP 完整解压到一个单独的临时目录，先不要直接解压到旧客户端上。
2. 打开旧客户端根目录，应能看到“七音音乐工作室.exe”和 resources 文件夹。
3. 进入这个旧目录的 resources，把原有 app 文件夹重命名为 app-v1.3-backup-20261006。
   如果这个备份名已经存在，换一个未使用的名字。不要覆盖已有备份。若重命名失败，停止并检查程序是否已退出。
4. 从本更新包复制 resources\app 这个完整的 app 文件夹，到旧客户端的 resources 中。
   更新后的结构应是：
   原客户端\七音音乐工作室.exe                  （原有文件，保留）
   原客户端\.runtime\...                      （原有组件，若存在，保留）
   原客户端\resources\app-v1.3-backup-20261006\ （旧应用和你放入其中的文件，保留）
   原客户端\resources\app\package.json         （新版 version 为 1.4.0-public.1）
   原客户端\resources\app\desktop\main.cjs
   不应出现 resources\app\app\package.json。
5. 只复制新的 app 文件夹。不复制更新包的外层目录，不替换根目录的 EXE / DLL / pak / locales / LICENSE / LICENSES.chromium.html，不覆盖 .runtime、个人项目或用户配置。
6. 旧目录根部的“客户端使用说明”等可能仍显示 v1.3，因为本包没有覆盖这些旧文件。新版说明以 resources\app\README.md、docs\COMPONENT_SETUP.md 和本说明为准。

为什么不建议合并覆盖：旧版有一些不在公开基础版中的历史报告、许可表述以及未使用的 QuickJS 文件。整体保留旧 app 为备份，再放入完整的新 app，可以确保正在运行的应用资源与公开基线一致，不需要删除文件。不要把旧 app 内容全部合并回新 app；你的个人作品可在确认路径后单独复制到应用目录之外，再从应用打开。

六、启动后检查
1. 从原来位置双击“七音音乐工作室.exe”。在“帮助 → 关于七音”确认显示 v1.4.0-public.1。
2. 先打开一份已保存工程的副本，试播放并另存新文件，确认结果后再继续正式工作。高级歌曲、识别工程和乐谱分别检查。
3. 应用更新文件本身没有任何识别运行库或模型。原 .runtime 不动，程序仍可能校验已有组件或提示重新准备；是否可直接使用取决于现有组件、路径、版本与系统环境。
4. 未装组件时可按指南选择官方安装方式；音频准备可能需要联网下载，点击前看清程序提示。不要为“试升级”而盲目重装已经有的组件。
5. OMR 使用另行安装的官方 Audiveris，在“配置五线谱识别”选择其程序。它独立采用 AGPL-3.0。新版保留现有配置文件，但外部程序路径仍须有效。
6. 缺 DLL、识别启动失败或系统发出安全警告时，先记录完整提示；不要下载不明 DLL 或关闭系统防护。

七、回滚（保留新版和升级后新作品）
1. 如果新版还能打开，先把升级后新增 / 修改的作品另存到应用目录之外，再完全退出程序。
2. 在原客户端 resources 中，将当前 app 改名为一个未使用的名字，如 app-v1.4-public-backup-20261006。
3. 把之前保留的 app-v1.3-backup-20261006 改回 app。不要合并两个 app 文件夹，不要删除它们。
4. 从原路径重新启动原 EXE。先用升级前保存的工程副本验证；不能保证新版保存格式可被旧版读取。
5. 若升级后曾配置或重装可选组件，需要恢复旧运行状态时：完全退出程序，先把当前 .runtime 改名为一个新的备份名，再把升级前备份中的 .runtime 复制回原路径。不要覆盖唯一的组件备份，不要随意迁移到另一台电脑。
6. 只有确实需要恢复浏览器偏好时，才在退出程序后，用同样“当前目录先改名备份、旧目录复制回来”的方式处理此前备份的 %APPDATA% 应用目录。恢复旧配置可能使后来偏好 / 草稿不可见，先保存后来作品。没有必要时不要动用户配置。
